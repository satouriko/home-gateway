# 系统背景与维护边界

部署值、用户策略和运行版本以实时系统上下文为准。本文件描述各部分为何存在，不是当前状态快照。

## 两条网络路径

业务数据面由代理内核转发，承担用户设备的透明代理、DNS和分流。维护 Agent 自身的模型请求使用受保护的独立上游路径与解析，避免业务规则出错后维护者也消失。因此维护 Agent 的普通网络请求不能代表用户路径；业务实验应明确经过业务代理或隔离客户端。

## 权限与代码

受保护底座负责启动、凭据、独立联网、权限检查和失败恢复。可维护部分包括诊断、巡检分析、工具模块、方法技能和经验。Agent 在自己的源码工作区修改候选，经发布接口进入版本化的运行副本。运行副本只读，保护底座不执行未经隔离的候选代码。

运维工具模块在不同于 Agent 的低权限身份运行，具有只读系统、临时目录和 CPU/内存/进程/执行时限，无法读取 Agent 凭据或写正式配置。工具可以扩充只读观测与分析；实际修复通过受保护的操作接口执行。运行异常会禁用坏版本或恢复前版。

## 主动维护

常驻程序持续采集，先处理能确定的小范围故障，保存故障工单和操作效果。定时任务和异常会唤起维护 Agent；反复故障、修复后复发、证据缺口与工具误判，意味着需要检查并可能修改程序，而不是重复同一种操作。

固定探测只覆盖一部分业务。代理健康URL成功不等于所有应用可用，活跃连接采样不是完整流量计费。应用拒绝、账号与限流要和传输失败分开。物理链路和外部服务的问题需要对照证据，不用小样本直接宣称已定位。

## 策略与方法

用户偏好属于独立配置；维护者依据当前批准的目标优化，也接受用户明确提出的新目标。方法技能只描述可复用的判断方法。经验是带时间与证据的材料，可能被修订或作废，不能凌驾于实际配置和观测。

运行时无法访问模型API时，本地保护程序继续工作。不能假装离线推理；保留任务和证据，恢复连接后继续。
