# 系统背景与维护边界

部署值、用户策略和运行版本以实时系统上下文为准。本文件描述各部分为何存在，不是当前状态快照。

## 两条网络路径

业务数据面由代理内核转发，承担用户设备的透明代理、DNS和分流。维护 Agent 自身的模型请求使用受保护的独立上游路径与解析，避免业务规则出错后维护者也消失。因此维护 Agent 的普通网络请求不能代表用户路径；业务实验应明确经过业务代理或隔离客户端。

## 权限与代码

受保护底座负责启动、凭据、独立联网、权限检查和失败恢复。可维护部分包括诊断、巡检分析、工具模块、方法技能和经验。Agent 在自己的源码工作区修改候选，经发布接口进入版本化的运行副本。运行副本只读，保护底座不执行未经隔离的候选代码。

运维工具模块在不同于 Agent 的低权限身份运行，具有只读系统、临时目录和 CPU/内存/进程/执行时限，无法读取 Agent 凭据或写正式配置。工具可以扩充只读观测与分析；实际修复通过受保护的操作接口执行。运行异常会禁用坏版本或恢复前版。

## 主动维护

常驻程序持续采集，先处理能确定的小范围故障，保存故障工单和操作效果。定时任务和异常会唤起维护 Agent；反复故障、修复后复发、证据缺口与工具误判，意味着需要检查并可能修改程序，而不是重复同一种操作。

固定探测只覆盖一部分业务。代理健康URL成功不等于所有应用可用，活跃连接采样不是完整流量计费。应用拒绝、账号与限流要和传输失败分开。物理链路和外部服务的问题需要对照证据，不用小样本直接宣称已定位。

## 策略与方法

用户偏好属于独立配置；维护者依据当前批准的目标优化，也接受用户明确提出的新目标。方法技能只描述可复用的判断方法。经验是带时间与证据的材料，可能被修订或作废，不能凌驾于实际配置和观测。

运行时无法访问模型API时，本地保护程序继续工作。不能假装离线推理；保留任务和证据，恢复连接后继续。


## 程序仓库

公开仓库为 https://github.com/satouriko/home-gateway ，程序维护、用户偏好和正式部署统一提交到 main。正式发布的 skill、诊断程序、工具和通过验收的偏好会立即触发独立程序检查并提交推送，不依赖维护者记得再调用 Git，内容未变化时不产生提交。推送失败保留待同步请求，由独立定时器重试，不撤销本地已验证的版本。同步会先检查远端历史；未部署的远端程序变更或冲突会停止同步，不能强推覆盖。

当前系统上下文 source_control 给出仓库、分支、最近尝试、最近成功推送的提交和时间，以及安全的失败原因。说明文档不代表已推送；pending=true 表示仍有未确认推送的发布请求。本地发布返回的 source_control_sync 只表示同步已请求，必须核对 pending=false 且实际成功状态才能向用户说已保存到 GitHub。同步失败不影响网关运行。

不要把凭据、订阅或节点内容、对话、日志、诊断历史提交 Git。部署模板使用凭据占位符。改动先按现有发布接口测试并生效，再核对 Git 版本；原始候选不代表已发布。上游升级遵循 CONTRIBUTING.md 与 docs/UPSTREAM.md，不能将远端代码直接覆盖正式服务。

## 原生自动化与聊天

常规 AI 复核由 DSH 原生 Automation 的独立执行方式触发，任务身份保持稳定。时间、内容和删除操作以原生任务管理为准；默认约四小时一次，程序准入仍检查谷价、最小间隔、日预算、观测新鲜度与空间。程序三分钟巡检不调用模型，也不向任务来源会话反复追加消息。没有实际 AI 执行就不创建会话。

每次真正执行都启动新的有界 headless DSH 进程和会话，结束释放内存及会话写锁。原生任务历史保存已启动、完成、失败、跳过、被抢占或过期的实际回执，并链接到独立会话。来源会话只承载任务来源信息，不累计历次巡检上下文。经验和必要事实通过有界实时上下文与按需读取传递，不能把全部旧对话当成下一轮提示。

常规任务不能拖入峰价或长期占用资源；未完成、取消和截断不能算成功。新故障抢占常规复核，独立紧急维护不依赖 Web 调度成功。用户继续某次后台聊天后，该会话按普通用户聊天保留。删除任务后不会自动重新创建；用户明确要求恢复才按保存的定义重新创建。公开备份只包含任务定义与启用偏好，不包含会话标识、聊天或执行历史。
